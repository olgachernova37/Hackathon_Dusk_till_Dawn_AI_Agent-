## 2. Вимоги до партнерських призів (Targeted Sponsor Prizes)

Проєкт інтегрує три екосистеми для виконання критеріїв одразу кількох спонсорських номінацій:

### A. The Graph ($5,000 Track: Best AI Tooling or AI Use Case with The Graph - Start Fresh)
- **Вимоги:**
  - Використовувати живі дані через Graph-провайдер (наприклад, Subgraph Studio API-ключі або Subgraph MCP). Моковані, локальні чи статичні дані не зараховуються[cite: 2].
  - Робити змістовну роботу з даними (логіка, прийняття рішень, автоматизація або інтерфейс природною мовою), а не просто виводити сирий результат запиту[cite: 2].
  - Відкритий репозиторій із чітким `README.md` або `SKILL.md`[cite: 2].

### B. World (🤳🏼 Selfie Check — призовий фонд $3,500; до 3 команд по $1,166)
**Завдання:** побудувати й продемонструвати реалістичний Selfie Check flow, який показує, де
низькофрикційний біометричний credential із середнім рівнем довіри корисний для
**risk, eligibility, fairness, continuity або abuse prevention**.

- **Кваліфікаційні вимоги (дослівно з трек-сторінки):**
  1. Використати Selfie Check або сумісний World ID credential flow **змістовно** (не просто логін).
  2. Трактувати Selfie Check саме як сигнал **risk / eligibility / fairness / continuity / abuse-prevention**.
  3. **Обов'язковий `FEEDBACK.md`** рівно за цими чотирма пунктами:
     - SelfieCheck docs та integration flow;
     - Developer Portal: навігація, пошук, product discovery, guidance для відладки;
     - Sandbox App: стани, proof flows, тестові користувачі, помилки та edge cases;
     - що було **незрозумілим, відсутнім, зламаним або важким для тестування**.
  4. Показати робочий застосунок.

- **Технічні факти (docs.world.org/world-id/credentials/11):**
  - **Credential ID: `11`**. Статус — **Beta**.
  - Перевіряє **liveness + facial similarity**: що це жива людина і що користувач, який
    повертається, — **та сама людина**. Повертає proof про проходження перевірки, **не числовий score**.
  - **Assurance: medium.** НЕ дає гарантії one-person-one-account (на відміну від Orb).
  - **Термін дії: 90 днів** — дефолтне вікно sybil-стійкості. Після 90 днів неактивності
    користувач проходить камера-флоу повторно. ⭐ Саме це вікно ми використовуємо як сигнал **continuity**.
  - **Передумови для юзера:** лише встановлений World ID App. Orb / паспорт не потрібні.
  - **Інтеграція:** через IDKit — deep link на мобільному, QR-код на десктопі.

- **🚨 Блокери доступу (почати НЕГАЙНО, обидва мають lead time):**
  1. **Selfie Check закритий feature-флагом.** Треба написати на **developers@toolsforhumanity.com**,
     щоб увімкнули для нашого `app_id`. Без цього флоу не запуститься.
  2. **Sandbox-застосунок відсутній у публічних сторах.** Встановлення лише через
     **TestFlight (iOS)** або **приватне посилання Google Play (Android)**.

- **Тестування в Sandbox (docs.world.org/world-id/sandbox/testing-selfie-check):**
  - Матриця станів користувача — **Hot / Cold / Semi-cold**:
    - **Hot** — World ID вже встановлений → одразу face matching (або enrollment, якщо Selfie Check уперше).
    - **Cold** — новий користувач: встановлення → створення акаунта → Selfie Check.
    - **Semi-cold** — наявний користувач перевстановлює на новий девайс → account recovery → Selfie Check.
  - **Відомі обмеження:** semi-cold стабільно працює на **Android**, на **iOS є прогалини**
    (зокрема redemption інвайт-коду посеред флоу). Обробка invite code відрізняється між платформами.
    ⇒ **Демо-відео записуємо на Android.**
  - Sandbox призначений лише для валідації інтеграції — не для production sign-off чи навантажувальних тестів.

### C. Bazantic (призовий фонд $3,000 на три треки)

**Огляд треків:**

| Трек | Приз | Наш статус |
|---|---|---|
| 🤖 Help an Agent Use Your Hackathon Project | $1,000 (2×$500) | **⛔ НЕДОСТУПНИЙ — лише для Continuity Track.** Ми — Start Fresh. |
| 🍳 **Best Recipe that uses EthGlobal Sponsor APIs** | $500 / $300 / $200 | ✅ **ОСНОВНА ЦІЛЬ** |
| 👨‍🍳 Agentify a New API | $500 / $300 / $200 | 🔶 Стретч — стекається з основним (див. нижче) |

#### 🍳 Основна ціль — Best Recipe (кваліфікаційні вимоги, усі обов'язкові)
1. Створити акаунт на `bazantic.com`.
2. Створити **x402/MPP Gateway** у Bazantic для свого проєкту.
3. Використати **щонайменше ще один сервіс**, який *або* вже доступний у каталозі Bazantic,
   *або* надається спонсором ETHOnline.
4. Створити **recipe, що використовує обидва сервіси в одному робочому потоці**.
5. **Кінцевий результат має змістовно залежати від обох сервісів** — не два незалежні виклики поруч.
6. Показати **виконання завдання від початку до кінця у screen recording**, що є частиною сабміту.
7. **Вказати username акаунта Bazantic** (email або GitHub handle) у формі подачі —
   інакше recipe не буде зараховано нам.

> **Еталонний приклад від Bazantic:** Uniswap API `GET /swap` → отримані транзакції передаються
> у 1inch Trace API `GET /transaction-trace` → логи. Тобто **вихід сервісу A стає входом сервісу B**.
> Суддя має побачити, як дані перетікають через цей стик. Проєктуємо саме так.

#### 👨‍🍳 Стретч — Agentify a New API
- Додати сервіс, якого **не було** в Bazantic **І** якого немає в API спонсорів на момент старту івенту.
- Створити робочий Gateway для цього сервісу + recipe, що використовує обидва сервіси.
- Пояснити у відео, як інші білдери можуть перевикористати цей сервіс.
- ⭐ **Стекується з основним треком:** «Best Recipe» вимагає, щоб другий сервіс уже був у Bazantic
  або від спонсора; «Agentify» — щоб НЕ був. Для *одного* сервісу це взаємовиключно, але для
  *одного проєкту* — ні. Recipe із трьох сервісів (наш gateway + API спонсора + новий API)
  кваліфікується **в обидва треки**. Рішення приймаємо в суботу опівдні, за замовчуванням — НІ.

## 3. Архітектура та структура додатку: "Human-Gated AI Copilot"

- **Фронтенд:** Next.js (React) + Tailwind CSS.
